Minimum Spanning Tree: Kruskal vs Prim

Both algorithms rely on the cut property: for any split of the nodes into two groups, a lightest edge crossing the split belongs to some MST. Kruskal scans edges from light to heavy and uses a DSU to skip edges that would close a cycle. Prim grows one tree and always adds the lightest edge leaving it (module 04). Drag nodes to rearrange.

Kruskal or Prim?

Kruskal · O(m log m)
  • Sort the edges, then one DSU unite per edge.
  • Best when you are given an edge list, which is the usual contest input.
  • Stop early after n − 1 edges.
  • Same idea also gives "minimum bottleneck path" and offline "is u connected to v using edges ≤ w?" queries.
Prim · O(m log n) with a heap, O(n²) without
  • Looks like Dijkstra, but the key is the edge weight, not the distance from the root.
  • The O(n²) array version wins on dense graphs (complete graphs given by coordinates, n ≈ 5000).
  • Only grows the root's component: on a disconnected graph, restart from an unvisited node.
// Kruskal with DSU (path compression + union by size)
vector<int> p(n), sz(n, 1); iota(p.begin(), p.end(), 0);
function<int(int)> find = [&](int x) { return p[x] == x ? x : p[x] = find(p[x]); };
sort(edges.begin(), edges.end());               // edges as {w, u, v}
ll total = 0; int used = 0;
for (auto [w, u, v] : edges) {
  int a = find(u), b = find(v);
  if (a == b) continue;                         // would close a cycle
  if (sz[a] < sz[b]) swap(a, b);
  p[b] = a; sz[a] += sz[b]; total += w;
  if (++used == n - 1) break;
}
// used < n - 1 at the end → the graph is disconnected

If all edge weights are distinct, the MST is unique. With ties, Kruskal and Prim can pick different trees, but the total weight is always the same. Sources: cp-algorithms: Kruskal with DSU · cp-algorithms: Prim.
