Binary Search on the Answer

Split the array into k contiguous parts so that the largest part sum is as small as possible (module 02, worked example 1). Each step guesses a limit x and runs the greedy O(n) check. Its result tells us which half of the range to throw away.

    bool ok(ll x) {                        // can we use ≤ k parts, each sum ≤ x?
  int parts = 1; ll cur = 0;
  for (ll v : a) {
    if (v > x) return false;           // one element alone is too big
    if (cur + v > x) { parts++; cur = 0; }   // greedy: start a new part
    cur += v;
  }
  return parts <= k;
}
ll lo = max(a) - 1, hi = sum(a);       // ok(lo) = false, ok(hi) = true
while (hi - lo > 1) { ll m = lo + (hi - lo) / 2; (ok(m) ? hi : lo) = m; }
// answer = hi
    Why it works: if a limit x is feasible, every larger limit is feasible too. The predicate looks like F F F … F T T T, and binary search finds the first T in ⌈log₂(range)⌉ checks.
